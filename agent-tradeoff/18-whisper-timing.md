# 18: Typed whispers reach the village (timing and Turnstile fixes)

Live finding (2026-10-21, https://rumourtown.dev): a typed whisper reached the Worker and came back as a correct signed claim (`/interpret` 200 in 3.1 s, kind "cheating" about Jonah), yet the sheet showed "The town's gossip is resting". A second attempt made no network request at all. Diagnosis: the flow's six-second deadline starts before Turnstile's first invisible challenge, which can take several seconds on first use, so the overall step times out; and after one use the Turnstile widget is not re-armed, so the next `getToken()` never resolves. Fix in `apps/rumortown/src/net/` (turnstile.ts, whisperFlow.ts, interpret.ts) with a minimal hook in `apps/rumortown/src/ui/whisper.ts`.

1. **Scope the deadline.** The 6 s AbortController deadline covers only the `/interpret` request and response parsing. Turnstile token acquisition gets its own budget (12 s on first use, 6 s after), and `/pubkey` is fetched once per session and cached in memory (prefetch it when the sheet opens).
2. **Pre-warm.** When the whisper sheet opens, start loading the Turnstile script and render the invisible widget immediately so a token is ready by the time the player finishes typing. Keep one ready token; Turnstile tokens expire after about five minutes, so refresh on expiry and after each use (`turnstile.reset(widgetId)` then `execute`), and never resolve a `getToken()` call with a token that has already been used.
3. **Dead path.** After a token is consumed, the next `getToken()` must re-execute the widget and resolve; add a test with a fake `window.turnstile` that counts renders, resets and executes and asserts two consecutive tokens are distinct and both resolve.
4. **Honest status.** The sheet shows the step in progress: "Checking you're human…", then "Asking the village…", then the confirmation card. On a Turnstile failure show "Couldn't check you're human. Try again." with a retry button that re-arms the widget; on a timeout, "The village took too long. Try again." (not the resting line, which is for budget and limits only).
5. **Tests.** Flow tests with stubbed slow Turnstile (8 s) and fast interpret (1 s) must succeed; a stubbed interpret of 7 s must time out with the timeout line; a second whisper after a first must reach the stubbed fetch.
6. Do not change the Worker, the simulation or the replay pin. Typecheck, tests and build pass; commit per directory with plain messages starting `18:` (no co-author lines). Report to `agent-tradeoff/reports/18-report.md`; finish with STATUS: DONE or STATUS: BLOCKED.

## Exact dead path found by the controller (read apps/rumortown/src/net/turnstile.ts and whisperFlow.ts)
- `whisperFlow.run` races `turnstile.getToken()` against one shared 5.8 s deadline that also covers `/interpret`. When the race rejects, the token promise inside `getToken` keeps running with `cancel` set; a later `getToken()` sees `cancel` defined and rejects immediately with 'turnstile', so the second whisper never reaches the network.
- Fix shape: give `TurnstileClient` a `warm()` that loads the script and pre-acquires one token (single use, cached for at most 240 s); `getToken()` hands out the cached token and immediately warms the next, waits on an in-flight acquisition instead of rejecting, and never leaves a stale `cancel`; `whisperFlow` uses separate budgets (token: 12 s first time, 6 s after; interpret: 6 s from its own start), exposes `warm()` (which also prefetches `/pubkey`), and maps 'timeout' to "The village took too long. Try again." Update `net.test.ts` expectations accordingly (some current tests assert the shared deadline and the reject-while-busy behaviour; change them to the new contract).
- The controller already shipped the SEO assets (public/robots.txt, sitemap.xml, llms.txt, manifest.webmanifest, icon.svg, icon PNGs, og.jpg, about.html and the Vite entry); task 17 should treat those as done and do the remaining head tags, JSON-LD, noscript, tests.
